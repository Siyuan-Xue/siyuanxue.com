# Hermes chat bridge

Requires Node 22.12+; no npm dependencies. Run `HERMES_API_KEY=... node services/hermes-chat/server.mjs` with the secret supplied securely by the environment (never paste a real key into shell history). Production setup is in `ops/README.md`.

The bridge trusts `X-Real-IP` only behind a loopback Nginx proxy which overwrites it. Do not expose port 8643. Only POST `/chat-api` and GET `/chat-api/health` exist. Accepted JSON is exactly `{messages:[{role:"user"|"assistant",content:string}]}`. No runtime overrides, tools, system messages, or caller sessions are accepted. Limits: 32 KiB body, 24 messages, 4000 UTF-16 code units/message, 16000 total; alternating from user, ending in user. Six requests per IP per rolling minute, two concurrent per IP, four total. Invalid body requests also consume admission quota. At most 10000 IP records are retained; idle records expire after a minute and a full table rejects new clients.

Upstream requests use model alias `hermes`, `stream:true`, a random session ID, and the private profile API key. The separate website profile fixes GLM-5.3/high reasoning, a four-turn and 120-second run budget, disabled long-term/profile memory, and exactly two read-only public-web tools: `web_search` and `web_extract`. The bridge does not provide tool isolation itself. Fresh upstream session IDs prevent cross-request history retrieval; Hermes still retains its native sessions and logs according to the profile's existing settings.

SSE is decoded incrementally across UTF-8 boundaries. Only `choices[0].delta.content` is emitted; internal events, reasoning, IDs and headers are discarded. Success ends in `[DONE]`. Upstream errors/truncation produce a generic `event: error` with `{"error":"stream_error"}` and no DONE. Before headers, upstream failure returns HTTP 502. Total timeout is 120 seconds and downstream disconnect aborts upstream. No request body or upstream error is logged by the bridge. Health only indicates bridge availability, not model readiness.

`createChatServer(options)` exports an unbound HTTP server for tests. Run `node --experimental-strip-types --test tests/hermes-chat.node.ts` for real Node socket behavior; `bun run test` invokes this suite too. The frontend stores the current visit's bounded messages and draft in browser `sessionStorage` and sends that visible history on each request. There is no extra website database. Clearing the conversation or closing the browser session removes that client-side continuity; this does not disable Hermes's separate native session/log persistence.

The checked-in [website-SOUL.md](website-SOUL.md) is the reviewed identity template for 小薛 / lowercase `xue`. [website-profile.yaml](website-profile.yaml) is a documented, non-secret partial overlay, not a complete Hermes profile. Merge it into the backed-up `website-chat` profile while preserving the existing `zai` model structure, `https://open.bigmodel.cn/api/paas/v4` base URL, `glm-5.3` selection, secrets, disabled skills, session/log settings, and unrelated fields. The values shown are authoritative for their listed paths, including replacement of lists and the complete `mcp_servers` map. Copy the SOUL template to that profile's `SOUL.md`; use a new session after changing it because Hermes freezes context files at session start.

Hermes v0.21.1 profile isolation is version-specific. An explicit `platform_toolsets.api_server: [web, no_mcp]` selects the native web toolset and prevents MCP inheritance, while `agent.disabled_toolsets: [kanban, context_engine]` suppresses implicitly recovered native/context tools at the final resolution step. `mcp_servers: {}` removes configured MCP servers. The effective API-server toolsets must resolve to `['web']`, and the raw runtime definitions must be exactly `['web_extract', 'web_search']`; no shell, file, browser, MCP, memory, skills, delegation, scheduling, or administrative tool may appear. Re-audit those names and the `_get_platform_tools` behavior after every Hermes upgrade.

Tavily is explicitly pinned for both capabilities with `provider_tier.tavily: free`, which opts into native keyless requests and needs no paid key. Keyless fallback and one-shot rescue remain enabled, so availability and result coverage are best-effort and vendor-rate-limited. Search results are untrusted and can contain unrelated namesakes. The v0.21.1 deployment audit observed a public search in about 3.5 seconds and public homepage extraction in about 3.2 seconds; these observations are not latency guarantees. Loopback and cloud-metadata extraction targets were refused before provider dispatch.

The separate `wechat-public` profile remains no-tools with `agent.disabled_toolsets: ['all', 'context_engine']`; do not apply the website overlay to it. Weixin administrative command gating must use the actual QR owner's ID in `allow_admin_from`; an empty list disables that gate. Other users should only have new/reset/stop commands. No Hermes source patch is required.
