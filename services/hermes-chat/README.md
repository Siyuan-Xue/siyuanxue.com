# Hermes chat bridge

Requires Node 22.12+; no npm dependencies. Run `HERMES_API_KEY=... node services/hermes-chat/server.mjs` with the secret supplied securely by the environment (never paste a real key into shell history). Production setup is in `ops/README.md`.

The bridge trusts `X-Real-IP` only behind a loopback Nginx proxy which overwrites it. Do not expose port 8643. Only POST `/chat-api` and GET `/chat-api/health` exist. Accepted JSON is exactly `{messages:[{role:"user"|"assistant",content:string}]}`. No runtime overrides, tools, system messages, or caller sessions are accepted. Limits: 32 KiB body, 24 messages, 4000 UTF-16 code units/message, 16000 total; alternating from user, ending in user. Six requests per IP per rolling minute, two concurrent per IP, four total. Invalid body requests also consume admission quota. At most 10000 IP records are retained; idle records expire after a minute and a full table rejects new clients.

Upstream requests use model alias `hermes`, `stream:true`, a random session ID, and the private profile API key. The separate website profile fixes GLM-5.3/high reasoning, Asia/Shanghai time, a four-turn and 120-second run budget, native website memory writes disabled, automatic background review disabled, and eight reviewed read-only tools: one current-time function, two native web functions, and five bounded memory/knowledge readers from the website plugin. The bridge does not provide tool isolation itself. Fresh upstream session IDs prevent cross-request history retrieval; Hermes still retains its native sessions and logs according to the profile's existing settings.

SSE is decoded incrementally across UTF-8 boundaries. Only `choices[0].delta.content` is emitted; internal events, reasoning, provider IDs and headers are discarded. Requests without a protocol header use the legacy stream: success ends in `[DONE]`, while a streamed failure ends with a redacted `event: error` and no DONE. Callers opt into the AI SDK stream only with the exact header `X-Chat-Protocol: ui-message-v1`; the response then carries `X-Vercel-AI-UI-Message-Stream: v1` and emits `start`, optional text frames, and either `finish` plus `[DONE]` or a safe `error` plus `[DONE]`. Safe error codes are `quota_exhausted`, `authentication_failed`, `rate_limited`, `context_limit`, `timeout`, `upstream_unavailable`, `interrupted`, `invalid_request`, `body_too_large`, and `stream_error`. Failures detected before streaming return JSON: authentication is HTTP 401; quota and rate limits are 429; context or invalid input is 400; oversized bodies are 413; timeouts are 504; unavailable or unclassified upstream failures are 502. Total timeout is 120 seconds, downstream write waits are bounded, and downstream disconnects abort upstream. No request body or upstream error is logged by the bridge. Health only indicates bridge availability, not model readiness.

`createChatServer(options)` exports an unbound HTTP server for tests. Run `node --experimental-strip-types --test tests/hermes-chat.node.ts` for real Node socket behavior; `bun run test` invokes this suite too. The frontend stores the current visit's bounded messages and draft in browser `sessionStorage` and sends that visible history on each request. There is no extra website database. Clearing the conversation or closing the browser session removes that client-side continuity; this does not disable Hermes's separate native session/log persistence.

The checked-in [assistant-SOUL.md](assistant-SOUL.md) is the canonical, channel-independent identity template for 小薛 / lowercase `xue`. It deliberately keeps stable facts about Boss in curated memory rather than duplicating a biography. [website-profile.yaml](website-profile.yaml) and [wechat-public-profile.yaml](wechat-public-profile.yaml) are documented, non-secret partial overlays, not complete Hermes profiles. Merge each into its named, backed-up profile while preserving model/provider structures, secrets, identity and transport settings, disabled skills, session/log settings, and unrelated fields. The values shown are authoritative for their listed paths, including replacement of lists and the complete `mcp_servers` map. Copy the canonical SOUL template to each applicable profile's `SOUL.md`; use a new session after changing it because Hermes freezes context files at session start.

Hermes v0.21.1 profile isolation is version-specific. The native `website-readonly` plugin returns fresh current time, reads fresh curated memory from the default and all named profiles, and reads inert native skill text and accessible published site files. Install its two files only in the `website-chat` and `wechat-public` profiles' `plugins/website-readonly/` directories before applying their overlays; registration rejects the default, owner, custom, and every other profile. The [read-only policy and operation audit](READONLY.md) documents exact schemas, paths, pagination, exclusions and actual-runtime checks. Each public profile explicitly selects `[web, website_readonly, no_mcp]` on its public platform, with other platforms empty, `mcp_servers: {}`, and `agent.disabled_toolsets: [kanban, context_engine]`. The missing-plugin case exposes only the two native web tools; deployment still fails because the six required plugin tools are missing. Re-audit after every Hermes upgrade.

The public profiles can read other profiles' curated MEMORY.md / USER.md without recalling their raw transcripts or sharing a writable profile home. Boss explicitly authorizes sharing all curated memory and all content returned by the readers, including personal life and relationships, in both website languages and guest channels. Read-only is an operation boundary, not a public-information-only topic filter. The canonical SOUL and the plugin prompt both carry this authorization; missing facts must not be invented. Credential redaction remains in force. A bounded prompt preview refreshes every upstream session; tools read full text through explicit pagination within the stated 1 MiB/file bound. Source memories are never synchronized or modified by this plugin. Native session/log persistence remains separate.

Tavily is explicitly pinned for both capabilities with `provider_tier.tavily: free`, which opts into native keyless requests and needs no paid key. Keyless fallback and one-shot rescue remain enabled, so availability and result coverage are best-effort and vendor-rate-limited. Search results are untrusted and can contain unrelated namesakes. The v0.21.1 deployment audit observed a public search in about 3.5 seconds and public homepage extraction in about 3.2 seconds; these observations are not latency guarantees. Loopback and cloud-metadata extraction targets were refused before provider dispatch.

The `wechat-public` overlay gives future guest conversations the same eight read-only functions through the `weixin` platform and leaves `api_server`/`cli` empty. It contains no credentials, account IDs, or login/transport changes. Weixin administrative command gating remains separate and must use the actual QR owner's ID in `allow_admin_from`; an empty list disables that gate. No Hermes source patch is required.

Weixin voice uses the native local STT pipeline. Merge [voice-profile.yaml](voice-profile.yaml) into the default, `xue-owner`, and `wechat-public` profiles after backing up their configs. Provision the complete cached multilingual faster-whisper base snapshot at the configured local directory first; this avoids Hugging Face metadata network checks during cold starts. Set both global and local STT language to an empty string for auto-detection, and ensure `HERMES_LOCAL_STT_LANGUAGE` is not forcing a language. The vocabulary prompt helps with recurring names but cannot guarantee proper-noun accuracy. Install [voice-context](voice-context/__init__.py) with its manifest into those three profiles' `plugins/voice-context/` directories, and append `voice-context` to each existing enabled-plugin list. Its native `pre_gateway_dispatch` hook only rewrites Weixin audio event text to preserve voice provenance; it registers no tools and leaves sender identity, attachments, routing and authorization fields untouched. The central gateway prepends the actual transcript afterwards. Uncertain transcription should be clarified before becoming memory; this is a model instruction, not a deterministic transcript-quality gate.

After configuration changes, restart the gateway. Existing sessions may retain their original SOUL context; the per-message voice hook also carries the clarification instruction so it applies to ongoing conversations. Validate every voice-enabled profile with the installed Hermes Python and `HERMES_HOME` using [verify-voice.py](verify-voice.py) `--hermes-source /path/to/hermes-agent`. Add `--audio /path/to/cached.silk` to replay a clip through native transcription and final input enrichment without model calls or outgoing messages. Re-run [verify-readonly.py](verify-readonly.py) against both guest profiles to verify final model-visible tools and write vetoes. Recheck native hook/enrichment behavior after Hermes upgrades.
