# Public Hermes chat

User approved adding `/chat/` to both existing language sites, for every visitor with chat only, no tools or long-term memory, and request/concurrency limits. The user also wants a separately configured Weixin channel usable by many people. The official Weixin QR binds one bot; a reusable contact/invitation QR is dependent on Tencent and must not be falsely promised.

Use the installed Hermes v0.21.1 official API server on `127.0.0.1:8642` in a fresh `website-chat` profile. Keep the private default profile unchanged. Website model is GLM-5.3, reasoning high, streamed responses. Disable every tool, persistent memory, profile memory, skills and MCP in the public profile. Weixin gets its own `wechat-public` profile with chat-only toolsets, memory disabled, open DMs, group delivery disabled, and owner-only administrative slash commands.

The existing website is bilingual static Astro with English at siyuanxue.com and Chinese at xuesiyuan.com. Add a same-origin `/chat-api` Node HTTP bridge on loopback port 8643, exposing only `POST /chat-api` and a safe health route. It validates a bounded `{messages:[{role:user|assistant,content:string}]}` payload, ignores/rejects all runtime overrides, and sends a fixed Hermes model alias and streaming flag server-to-server. Never send GLM or Hermes API keys to visitors. Generate a fresh random upstream session id for each request, so supplied conversation history is the only continuity and users cannot read saved sessions. Keep browser history in memory only; clearing the chat starts over.

Defenses are functional requirements: body <= 32 KiB, <= 24 messages, each <= 4000 characters, total <= 16000 characters, last role user, alternating roles from user; 6 requests/IP/minute, 2 concurrent/IP, 4 total; HTTP 429 for limits; upstream timeout 120s; abort upstream on disconnect; preserve SSE response streaming without exposing upstream diagnostic errors, headers, session identifiers or credentials. Deployment Nginx must overwrite the client IP header; bridge trusts it only because it listens on loopback. Require allowed Origin for browser POSTs; allow no-Origin for curl/API usage subject to limits. Restrict public method/path to the bridge. Do not expose raw management or Hermes API surfaces.

UI: a dedicated responsive /chat/ page within existing style, header entry on both languages, message list, labelled textarea, send/stop/new conversation controls, stream updates, visible busy/error/rate-limit states, keyboard submit with Shift+Enter newline and IME-safe handling, no raw HTML from model messages. Copy states AI, GLM-5.3, conversation is not shared with other visitors, avoid claiming no server logs. No unrelated website changes.

Ops: keep the current release deployment workflow and existing HTTPS/denial/locale behavior. Add narrowly scoped Nginx proxy includes to both current production domain configs and their tracked templates. Provide a root-reviewed systemd service/install script for bridge, with a root-owned mode 600 environment file containing Hermes API key, no GLM key in bridge. Run bridge under a dedicated unprivileged service account. Profile gateway is managed through official `hermes -p website-chat gateway install` with start/boot enabled. Keep archives/rollback backups and validate Nginx before reloading.

Acceptance: meaningful request-boundary and streaming/error tests; website check/test/build/output checks; static UI preview; real anonymous public chat reply in both sites; direct raw API not publicly reachable; service survives terminal close; zero public-profile toolsets; independent Weixin session after owner's scan. Second-user Weixin delivery and reusable QR must be reported unverified until actual evidence exists.
