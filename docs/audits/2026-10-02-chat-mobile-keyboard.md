# 手机聊天键盘展开与恢复

日期：2026-10-02。基线为已发布的 `1df24e4b6679b08972fc74d37272c63cb26c33ad`。用户指出手机端弹出键盘后的页面上移不合理。继续保留主页字体/文字色/背景、Baby图标、无侧栏及固定主页姓名。

## 根因与修正

旧代码只监听 `visualViewport.resize`，将整份文档高度改为可见高度；未处理视觉视口自身的上移及 `scroll` 事件。欢迎区域仍在缩水后的页面中居中，使用布局视口的 `vh` 留白，不能代表键盘上方的实际空间。规范区分视觉视口与布局视口，并说明软键盘可能缩小视觉视口及引发两种视口的滚动：[CSSOM View](https://drafts.csswg.org/cssom-view/#dom-visualviewport-offsettop)、[WICG官方示例](https://github.com/WICG/visual-viewport#example)。这里依据规范确认代码遗漏，不声称已经在实体手机复现同一浏览器的每个事件时序。

- 文档高度保持100dvh；手机聊天容器单独按可见高度和顶部偏移定位，同时监听resize/scroll、窗口变化及输入焦点，逐帧合并更新。不追加页面强制滚动或固定延迟。
- 根据聚焦与明显的可见高度损失进入键盘状态；按钮间切换焦点不会立即恢复欢迎页，视觉高度实际恢复后才退出。地址栏的小幅变化和双指缩放不误触发键盘布局。
- 键盘打开时收起欢迎标题、建议问题和页脚，输入框靠近可见底边，移除键盘之外的底部安全区留白。首次发送不再额外播放欢迎输入框下沉动画。
- 多行文本高度同时受可见高度和实际主区域剩余空间限制；错误/存储提示增删会重新计算。极小区域保留两侧操作按钮，长文本在输入框内滚动，提示可内部滚动，不挤出发送/停止控件。
- 旋转时使用新方向的布局高度建立参考，不把已被键盘压缩的高度当作完整高度。手机新对话清除焦点，避免无意再次打开键盘；桌面保留原有焦点体验。

## 验证与局限

先添加键盘展开/偏移/关闭、焦点转移、缩放/地址栏、方向切换的组件回归，旧实现失败，再实施修正。独立审查发现「键盘打开时旋转」与「极小高度+错误卡+长草稿」两个真实遗漏；分别通过红测试和本地浏览器尺寸实测确认后修正。

最终本地完整回归87项通过，0失败；类型检查0错误/警告/提示。双语构建通过，20项产物检查通过。专用键盘fixture只能通过本地预览显式 `--keyboard-fixture` 启用，不进入网站产物；默认预览行为保持原样。

Browser以390×844布局视口进行本地模拟；fixture明确标记“Simulated keyboard — not a device test”。检查中英文欢迎、首次发送、分块流、可编辑草稿、多行、错误提示、偏移与恢复，浏览器错误/警告为空：

| 模拟条件 | 实测结果 |
|---|---|
| 可见高度420，顶部偏移80 | 聊天区域80..500；输入外框442..492，距可见底边8px；文档仍高844 |
| 同高度继续偏移至110 | 聊天区域110..530；输入外框底部522，仍距底边8px |
| 键盘收起 | 聊天区域恢复0..844，页脚恢复，草稿“My next question”保留 |
| 可见高度180，长草稿+错误 | 两侧按钮完整可见；输入区不向视觉底边之外溢出 |
| 可见高度140，长草稿+错误 | 聊天区域80..220，scrollHeight140；输入区140..220、scrollHeight80；错误144..164可滚动；外框166..216、输入/发送175..207 |
| 正常桌面1280×720 | 顶栏姓名仍x=328、y=15.6015625、28.8px字；无键盘状态 |

自动回归中的方向切换在两个方向均保持coarse指针，继续聚焦并保留键盘遮挡，实际恢复新方向可见高度后退出紧凑布局。happy-dom缺少联合媒体查询/粗指针实现，新回归对此单独模拟，其他测试保持原设置。

**待处理：实体iOS/Android软键盘验收。** 本机没有可用的iOS Simulator运行环境，浏览器可调尺寸和事件fixture不能证明操作系统键盘动画、Safari版本差异或第三方输入法时序已验收。没有安装模拟器、接受系统许可或把模拟检查写成真机结果。
