## 7. 新模型接口的直接测试（23:13–23:30）

用户通过隐藏输入把接口地址、模型 ID 和密钥写到服务器 `~/hermes-new-model.env`（0600）。配置完成并核对四个 `.env` 后，该文件已于 23:52 删除。

- 接口：`https://llmapi.datatang.com/anthropic`（Anthropic Messages 兼容的中转网关），模型 `claude-fable-5-2`。
- 从服务器直接发了约 50 条很小的测试请求（密钥只在服务器进程内读取）。结果：
  - `POST /v1/messages` 用 `x-api-key` 或 `Authorization: Bearer` 都能通过；`GET /v1/models` 返回网关的网页，不能列模型。
  - 参数错误以 **HTTP 200** 加 `{"type":"error","error":{...}}` 返回：非默认 `temperature`、`thinking.type=enabled`、强制 `tool_choice` 都被拒绝；未知模型返回 HTTP 500。
  - **网关会在调用方的系统提示词之前注入它自己的提示词。**不带系统提示词询问时，模型回答自己是「Claude Code, Anthropic's official CLI」或「a Claude agent, built on Anthropic's Claude Agent SDK」；带一句很弱的人设时仍回答自己是 Claude Code。不同请求落到不同上游通道，用量里多出约 0.2k 或约 8k 的缓存 token。
  - 模型看到的工具名被网关改写成 `mcp__g__<数字>` 和 `mcp__app_<哈希>__ClientWebSearch` / `ClientWebExtract`；工具调用和结果回传正常。
  - 流式输出是标准 SSE 事件；小请求的首字节约 4–6 秒。
- Hermes v0.23.4 对这类地址的处理（读源码确认）：`model.provider: anthropic` 加 `model.base_url`；非 anthropic.com 主机走第三方路径，用 `x-api-key`，回放历史时去掉 thinking 块；Fable 系列使用 adaptive thinking 加 `output_config.effort`（取自 `agent.reasoning_effort`），不发送采样参数。
